# AI Calories Tracker App

A React Native (Expo) app that helps you track your calories with AI. Built with
[Expo Router](https://docs.expo.dev/router/introduction/) for navigation,
[Clerk](https://clerk.com) for authentication (email + password and Google), and
[Firebase Firestore](https://firebase.google.com/docs/firestore) for storing
user profile data.

## Features

- Beautiful, Dribbble-inspired Sign In / Sign Up screens
- Email + password authentication with email verification (via Clerk)
- Google OAuth sign-in (via Clerk SSO)
- Automatic user profile sync to Firebase Firestore (`users` collection)
- Protected routes with redirect handling

## Project structure

```
src/
  app/
    _layout.tsx            # ClerkProvider + status bar
    index.tsx              # Auth-aware redirect
    (auth)/
      _layout.tsx          # Guard: redirect signed-in users out of auth
      sign-in.tsx
      sign-up.tsx          # Includes inline verification step
    (app)/
      _layout.tsx          # Guard: redirect signed-out users to /sign-in
      home.tsx             # First protected screen
  components/               # Reusable UI: AuthInput, PrimaryButton, GoogleButton, Divider
  constants/theme.ts        # Colors, spacing, radii, shadows, font sizes
  hooks/useWarmUpBrowser.ts # Snappier Android OAuth
  lib/
    firebase.ts             # Firebase app + Firestore singleton
    users.ts                # upsertUser() -> Firestore "users" collection
```

## Get started

1. **Install dependencies**

   ```bash
   npm install
   ```

2. **Configure environment variables**

   Copy `.env.example` to `.env` and fill in the values:

   ```bash
   cp .env.example .env
   ```

   - **Clerk**: Create an application at
     [dashboard.clerk.com](https://dashboard.clerk.com), enable
     **Email + Password** and **Google** as authentication strategies, and copy
     your publishable key into `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY`.
   - **Firebase**: Create a Firebase project, add a Web App, copy the config
     values into the `EXPO_PUBLIC_FIREBASE_*` variables, and enable Cloud
     Firestore in the Firebase console.

3. **Build and run a dev client** (required because Clerk uses `expo-secure-store`)

   ```bash
   npx expo run:android   # or run:ios
   ```

   You can also use EAS Build to produce a development build for a real device.

## How authentication works

- The root layout wraps the app in `<ClerkProvider>` using a secure
  `tokenCache` from `@clerk/clerk-expo/token-cache` so sessions persist across
  app restarts.
- The unauthenticated user lands on `/(auth)/sign-in` (or `/sign-up`).
- After a successful sign-in/sign-up, the `(app)/_layout.tsx` guard listens for
  the loaded Clerk `User` and calls `upsertUser()` to save the basic profile
  (`uid`, `email`, `firstName`, `lastName`, `fullName`, `imageUrl`, `provider`,
  `createdAt`, `updatedAt`, `lastLoginAt`) to the Firestore `users/{uid}` doc.
- Signing out from the home screen returns the user to `/sign-in`.

## Notes

- This project uses Expo SDK 55 + React 19 + React Native 0.83.
- Typed routes are enabled via `experiments.typedRoutes`. If you add new routes
  the typed routes file at `.expo/types/router.d.ts` is regenerated by the
  Metro dev server on the next bundle.
- Email verification is required by default on Clerk; the sign-up screen
  handles the 6-digit code in-flow.
